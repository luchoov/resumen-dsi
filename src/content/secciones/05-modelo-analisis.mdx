### 5.1. Entrada del workflow de análisis

El análisis recibe principalmente el modelo de requerimientos: casos de uso, actores, glosario, modelo de dominio, requisitos especiales y restricciones conocidas.

<MermaidDiagram caption="Entradas del workflow de análisis" code={`flowchart LR
  CU[Casos de uso] --> ANA[Análisis]
  ACT[Actores] --> ANA
  GLO[Glosario] --> ANA
  DOM[Modelo de dominio] --> ANA
  RNF[Requisitos especiales] --> ANA
  ANA --> MA[Modelo de análisis]`} />

### 5.2. Salida del workflow de análisis

La salida central es el <strong>modelo de análisis</strong>. Este modelo contiene clases de análisis, realizaciones de casos de uso de análisis, paquetes de análisis y descripción de arquitectura desde la vista del modelo de análisis.

<MermaidDiagram caption="Artefactos del modelo de análisis" code={`graph TD
  MA[Modelo de análisis]
  MA --> CA[Clases de análisis]
  MA --> RCU[Realizaciones de casos de uso]
  MA --> PAQ[Paquetes de análisis]
  MA --> ARQ[Descripción de arquitectura]
  CA --> BCE[Entidad / Frontera / Control]
  RCU --> EST[Vista estática]
  RCU --> DIN[Vista dinámica]`} />

### 5.4. Qué es el modelo de análisis

<Definicion termino="modelo de análisis">
El <strong>modelo de análisis</strong> es una jerarquía de paquetes que contiene clases de análisis y realizaciones de casos de uso.
</Definicion>

Describe cómo los objetos conceptuales del sistema colaboran para satisfacer requisitos funcionales, todavía sin atarse a decisiones tecnológicas de diseño.

<EjemploReal titulo="Del requerimiento al modelo en la pizzería" dominio="Caso cátedra">
El requerimiento del pizzero es simple: "quiero gestionar los pedidos". El análisis lo convierte en modelo: aparece la realización del caso de uso "Registrar Pedido", y de ahí surgen las clases `Pedido`, `DetallePedido`, `Pizza` (entidades), la `PantallaRegistrarPedido` (frontera) y el `GestorRegistrarPedido` (control). Todavía no se decide si será MySQL o una pantalla web: eso es diseño.
</EjemploReal>

### 5.5. Cómo se construye el modelo de análisis

- <strong>Clases de análisis:</strong> se modelan con diagrama de clases y, si corresponde, máquina de estados.
- <strong>Realizaciones de casos de uso:</strong> tienen vista estática y vista dinámica.
- <strong>Paquetes de análisis:</strong> se modelan con diagrama de paquetes.
- <strong>Descripción de arquitectura:</strong> destaca paquetes, clases y realizaciones significativas.

<MermaidDiagram caption="Construcción incremental del modelo de análisis" code={`flowchart TB
  A[Identificar paquetes principales] --> B[Realizar casos de uso]
  B --> C[Descubrir clases BCE]
  C --> D[Asignar responsabilidades]
  D --> E[Revisar cohesión y acoplamiento]
  E --> F[Actualizar arquitectura lógica]
  F --> B`} />

<Callout tipo="atencion">
El modelo de análisis no reemplaza al diseño: lo prepara. Si aparecen decisiones de framework, base de datos o protocolo, probablemente ya estás pasando a diseño.
</Callout>
