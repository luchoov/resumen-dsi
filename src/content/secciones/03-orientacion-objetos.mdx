### 2.1. Qué es un objeto

<Definicion termino="objeto">
Un <strong>objeto</strong> representa una entidad individual e identificable, real o abstracta, con un rol definido en el dominio del problema.
</Definicion>

Todo objeto se entiende por tres dimensiones: <strong>identidad</strong>, <strong>estado</strong> y <strong>comportamiento</strong>.

<MermaidDiagram caption="Tres dimensiones de un objeto" code={`graph TD
  O[Objeto]
  O --> I[Identidad\nlo distingue]
  O --> E[Estado\nvalores actuales]
  O --> C[Comportamiento\nresponsabilidades]
  E --> A[Atributo + valor]
  C --> M[Mensajes y operaciones]`} />

### 2.2. Qué es una clase

<Definicion termino="clase">
Una <strong>clase</strong> describe un conjunto de objetos que comparten estructura, comportamiento, relaciones y semántica.
</Definicion>

Un objeto se crea a partir de una clase. A ese acto se lo denomina <strong>instanciación</strong>.

<EjemploReal titulo="Variedad de pizza vs. la pizza que te llevás" dominio="Caso cátedra">
La <strong>clase</strong> `VariedadPizza` describe qué es "una muzzarella": nombre e ingredientes. La pizza concreta de 8 porciones que se está preparando para el pedido número 47 es un <strong>objeto</strong> (una instancia) con su propia identidad. Mil clientes pueden pedir muzzarella, pero cada pizza horneada es un objeto distinto, todas creadas a partir de la misma clase.
</EjemploReal>

### 2.3. Estado, atributos y valores

El <strong>estado</strong> de un objeto puede entenderse como:

<EjemploClase titulo="Fórmula conceptual">
Estado = atributo + valor en un momento determinado
</EjemploClase>

Si la clase es <strong>SolicitudDeRequerimiento</strong>, algunos atributos podrían ser número, fecha de creación, descripción y estado actual. Si cambia de “Pendiente” a “Aprobada”, el objeto sigue siendo el mismo, pero su estado interno cambió.

### 2.4. Comportamiento y responsabilidades

El comportamiento indica qué puede hacer un objeto. En análisis suele expresarse como <strong>responsabilidades</strong> de alto nivel, no como métodos con signatura completa.

<EjemploReal titulo="El cajero del banco" dominio="Cotidiano">
Pensá en un cajero como objeto: su <strong>estado</strong> es el saldo de su caja y la sucursal donde trabaja; su <strong>comportamiento</strong> son responsabilidades como "depositar", "extraer" o "consultar saldo". No te importa cómo cuenta los billetes internamente: le mandás un mensaje ("quiero extraer 5000") y él responde. Eso es un objeto colaborando por mensajes.
</EjemploReal>

### 2.5. Abstracción

<Definicion termino="abstracción">
La <strong>abstracción</strong> consiste en concentrarse en las características esenciales de un objeto según la perspectiva del observador y el problema que se resuelve.
</Definicion>

### 2.6. Sistema orientado a objetos

Un sistema orientado a objetos se piensa como una red de objetos que colaboran enviándose mensajes. Las responsabilidades no deberían concentrarse en una única clase central.

<MermaidDiagram caption="Colaboración entre objetos" code={`sequenceDiagram

  P->>D: agregarProducto(producto, cantidad)
  G->>UI: mostrarConfirmacion()`} />

### 2.7. Clases en el dominio del problema

Se identifican clases buscando roles, lugares, cosas, organizaciones, conceptos, eventos o transacciones.

<MermaidDiagram caption="Ejemplo rico de clase UML: pedido" code={`classDiagram
  class Cliente {
    -nombre: String
    -email: String
    +actualizarEmail(email)
  }
  class Pedido {
    -numero: int
    -fecha: Date
    -estado: EstadoPedido
    +calcularTotal() Money
    +confirmar()
  }
  class DetallePedido {
    -cantidad: int
    -precioUnitario: Money
    +subtotal() Money
  }
  class Producto {
    -sku: String
    -descripcion: String
    -stock: int
    +reservar(cantidad)
  }
  class Direccion
  class Pago
  Pedido --> Cliente : pertenece a
  Cliente o-- Direccion : direcciones
  Pedido *-- DetallePedido : contiene
  DetallePedido --> Producto : referencia
  Pedido ..> Pago : solicita autorización
  Pago <|-- PagoTarjeta`} />

<Callout tipo="error">
No confundas clase con tabla. En análisis, una clase también tiene responsabilidades y colaboración; no es solo una bolsa de atributos.
</Callout>
